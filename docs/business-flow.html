L0 · 系统全景

五个入口 → 引擎内部六段流水线 → 平台四类回写动作。多租户以 teamId 贯穿全链路。

拓扑是「星型汇聚」而非流水线：5 个内置 Agent 之间互不通信、无依赖，协作只发生在聚合阶段（去重 / 仲裁 / 抑制）。这是与「Agent 链式传递结果」架构的根本差别。

L1 · 主流程：PR 事件端到端审查链路

以 Gitea 为例。Webhook 同步部分只做校验与分发，重活全部丢给 webhookExecutor 异步执行，避免平台侧超时重试。

L2 · 协调器：多 Agent 并行与超时降级

CompletableFutureCoordinator.review() 是全系统最核心的一函数：上下文增强 → Agent 展开 → 并行执行 → 独立限时等待 → 聚合 → 后处理。

L3 · 单 Agent：三段式流水线与三级降级

L4 · 结果聚合：去重 / 仲裁 / 误报抑制

ReportGenerator.aggregate() 把 N 个 Agent 的发现收敛为一份对外报告。仲裁权重：安全 100 > 逻辑 90 > 性能 70 > 架构 60 > 风格 10。

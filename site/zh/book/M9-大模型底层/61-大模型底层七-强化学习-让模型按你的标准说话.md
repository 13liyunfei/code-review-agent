## 一、痛点

你在应用层已经把"反馈闭环"做得很熟：第 40 讲的误报反馈、第 47 讲的记忆按证据迁移。但当你听说"模型是**强化学习（RL）**出来的"时，可能有两个反应：

**反应一："强化学习？那不就是打游戏吗，跟大模型有什么关系？"** → 你把强化学习只当成"玩游戏学走路"那种，没意识到它在大模型这里有一个最知名的应用——**RLHF**。

**反应二："模型对齐是厂商的事，关我什么事？"** → 你觉得对齐是训练侧内部细节，与应用层无关。→ 但**你每天都在享受对齐的成果**（能用一个 system prompt 就限定角色、模型不会乱答），也**每天都在承担对齐不完美的后果**（它可能"为了讨好而编造"）。

本讲要破除"RL 与 LLM 无关"和"对齐与应用无关"两个错觉。真相是：

> **RLHF 用人类对回答的偏好当『奖励』，通过强化学习让模型调整参数，最终优先输出人类更喜欢的回答——这一下解决了『模型会说话，但没被教该怎么说话』的问题。** 它和你在应用层做的反馈闭环（第 40 讲）**是同一个思想的两个层次**：模型层对齐它说出来的话，应用层对齐你期望的结果。

## 二、原理

### 2.1 一个比喻：会说话 ≠ 会挑合适的话说

预训练（第 59 讲）教会了模型"能说出通顺、丰富的语言"。但它没有内建"哪些话该说、哪些不该说"。就好像一个什么都懂的博学之人，**没人教过他在什么场合说什么**——他可能会把你不想听的重话、危险的建议、错误的信息都一本正经说出来。

**对齐（alignment）** 就是"教他怎么挑话说"。**RLHF 是其中最主流的方法之一。**

### 2.2 第一步：用 Bradley-Terry 模型训一个"打分器"

人类偏好很难直接定义成一条数学公式，但很好**比较**：同一个 prompt 下，让人说"回答 A 比回答 B 好"。这就是 RLHF 第一阶段的输入——**偏好对 (x, y_好, y_坏)**。

把"哪个更好"建模成一个打分器 r(x, y)，业界标准假设是 **Bradley-Terry 模型**：**"y_好 优于 y_坏"的概率 = 两者奖励之差的 sigmoid**：

```
P(y_好 ≻ y_坏 | x) = σ( r(x, y_好) − r(x, y_坏) )
```

σ 是 sigmoid。对这个假设做**最大似然估计**，就得到奖励模型的训练目标：

```
L_RM = − E[ log σ( r(x, y_好) − r(x, y_坏) ) ]
```

**一句话读这条式子**：让"好的回答"和"坏的回答"的奖励差 **越大越好**——这就是第 56 讲交叉熵"拉大正确项、压低错误项"在**偏好**上的版本。训练完，你就有了一个能给人打分、还能求梯度（可微分）的奖励函数 r。

### 2.3 第二步：强化学习——最大化奖励，但要"别跑偏"

有了奖励 r，第二步是**用它当信号更新策略模型 π_θ**（就是要对齐的那个 LLM）。最朴素的强化学习目标就是"让奖励尽量高"：

```
max_θ  E[ r(x, y) ]
```

但如果**只**最大化奖励，模型会走火入魔——它会学会"钻打分器的空子"（reward hacking）：为了让 r 高，产出一堆"人类打分高但实际没意义"的回答，甚至背离它原本的语言能力。于是必须加一个**约束**：**别离参考模型 π_ref 太远**。这就是加一个 **KL 散度惩罚项**：

```
max_θ  E[ r(x, y) − β · KL( π_θ(·|x) ‖ π_ref(·|x) ) ]
```

- **r(x, y)**：奖励项——往"人类觉得好"的方向拉；
- **KL 惩罚**：π_θ 与 π_ref 的 KL 散度，β 控制"允许偏离参考模型多远"——**防止模型为了高奖励而乱说、忘记本来会说的话**；
- **π_ref**：冻结的参考模型（通常就是 SFT 后的那个），作为"别忘本"的锚。

**这就是 RLHF 的核心动力结构**：一边用奖励把它往"人喜欢"拉，一边用 KL 把它往回拽、保持不崩——和你的第 44 讲上下文"准入+投放"、第 35 讲"分级防御"是**同一种"既要又要"的权衡设计**。

### 2.4 为什么 PPO 很贵、很难：四件套 + 在线采样

要对上面那条带 KL 约束的目标做优化，不能直接用普通梯度法，因为奖励 r 不是处处可导的"环境"（生成是一步一步采样的离散过程）。经典解法是 **PPO（近端策略优化）**，它把强化学习算法套进来，但代价是**训练时要同时维护四个模型**：

1. **策略模型 π_θ**——要更新的那个；
2. **奖励模型 r**——打分器（第 2.2 节训出来的）；
3. **参考模型 π_ref**——算 KL 惩罚用的冻结锚；
4. **价值模型（critic）**——估计每个状态的"期望收益"，用来算优势（advantage，即"这一步比平均好多少"）。

而且 PPO 需要**在线采样**：训练中不断用当前策略生成回答、让奖励模型打分、再反传更新——**这既慢（要反复跑大模型前向）又不稳定（四个模型 + 强化学习的方差都很大）**。这正是"对齐"长期被大厂垄断的原因：**不是"懂不懂"的问题，是"烧不烧得起这套训练"的问题。**

### 2.5 为什么现在都走 DPO/GRPO：把强化学习"闭式化"

**DPO（直接偏好优化）** 的关键洞察是：在 Bradley-Terry 假设下，第 2.3 节那条"max 奖励 − β·KL"的优化问题**有闭式解**——最优策略 π* 可以直接用奖励 r 和参考 π_ref 写出来。把这个闭式解**反代回**奖励模型的损失，就得到一个**不再需要独立奖励模型、也不需要在线采样**的损失函数：

```
L_DPO = −E[ log σ( β·[ log(π_θ(y_好|x)/π_ref(y_好|x)) − log(π_θ(y_坏|x)/π_ref(y_坏|x)) ] ) ]
```

（第 59 讲已出现过这条式子，这里讲清**它省掉了什么**）：DPO 把"先训奖励模型 → 再强化学习"压成**一步**，只用**偏好对 (x, y_好, y_坏) + 参考模型**就能动策略 π_θ。四件套砍成**两件**（策略 + 参考），训练门槛和稳定性大幅改善。

**GRPO（组内相对策略优化）** 再往前进一步：PPO 里那个价值模型（critic）是**用来算优势的基线**。GRPO 的洞察是——**基线不必是一个可训练的神经网络**，同一个 prompt 下**采一组（group）回答、用组内平均分当基线**就够了：

```
优势 = (单个回答的奖励 − 该组回答的平均奖励) / 该组奖励的标准差
```

这样**价值模型也砍掉了**（DeepSeek-R1 就用的这套）。**四件套 → PPO 四件 → DPO 两件 → GRPO 一件半**（策略 + 参考，参考也常被并掉），一路都在"省"，核心都是**同一个目标、同一个闭式解**的不断工程化简。

**这对你的意义**：作为应用层工程师，你不必实现这些，但要能读懂这条演进线的**逻辑**——**"复杂是因为奖励不可导 + 在线采样，简单是因为找到了闭式解"**。对应到你的系统，就是第 40 讲闭环：**复杂是因为"反馈是离散的、延迟的"，简化是因为你找到了"把反馈变成可计算的指标"**。

**PPO vs DPO vs GRPO 三方案深度对比表**（对齐算法选型速查）：

| 维度 | PPO | DPO | GRPO |
|---|---|---|---|
| **核心思想** | 在线强化学习，迭代优化策略 | 直接偏好优化，闭式解一步到位 | 组内相对优势，砍掉 critic |
| **需要的模型数** | 4 个（策略+价值+奖励+参考） | 2 个（策略+参考） | 1–2 个（策略 ± 参考） |
| **训练数据** | 在线采样（当前策略生成） | 离线偏好对 (x, y_好, y_坏) | 在线采样 + 组内对比 |
| **奖励来源** | 独立奖励模型 r(x,y) | 隐式（从偏好对反推） | 可验证奖励（判题/测例） |
| **稳定性** | 差（RL 方差大 + 多模型耦合） | 好（监督学习式的稳定） | 中（取决于组大小） |
| **显存占用** | 最高（四模型常驻） | 最低（两模型 + 离线） | 低（一模型 + 组内采样） |
| **工程复杂度** | 极高 | 低 | 中 |
| **效果上限** | 高（能利用完整奖励信号） | 中高（受限于偏好对质量） | 高（可验证域内接近 PPO） |
| **适用场景** | 大厂全量对齐、追求上限 | 中小团队快速对齐、开源标配 | 数学/代码等可验证域、推理强化 |
| **代表模型** | GPT-4（推测）、Claude（推测） | Llama 3 对齐、Qwen 对齐、开源主流 | DeepSeek-R1、DeepSeekMath、o1 类 |

**工程判据**：**DPO 是性价比最高的默认选项**——用 PPO 1/10 的工程复杂度拿到 90% 的对齐效果。**GRPO 是可验证域的新王者**——数学、代码这些有客观对错的场景，GRPO 用更低成本拿到了甚至超过 PPO 的效果（因为没有 reward model 的误差传递）。**PPO 仍然是"全领域对齐"的上限方案**，但它贵、难、不稳定，小团队不要碰。

### 2.6 你是对齐的受益者，也要承担它的副作用

**受益面**：正因为模型被对齐过，你才能用一个 **system prompt** 就限定它的角色与边界（第 11 讲），而不是靠"训练它成专家"。**这是应用层最省事的杠杆。**

**副作用面**：RLHF 可能让模型**为了迎合"人类偏好"而过度讨好**——它学会了"把话说得像正确的、像你想听的"，这种倾向有时反而是**编造的温床**（一本正经胡说更劝不了你）。这正是你为什么需要第 6 讲结构化失败、第 40 讲评测来"核实而不是轻信"。

**判据句（也是 M9 收官的总纲）**：**模型的『守规矩』是『按反馈练』出来的，不是天然如此；你在任何 Agent 里，都不能只依赖模型"天生可靠"，而要建自己的反馈闭环去持续校准它——正如它在模型层被校准过一样。**

### 2.7 前沿深挖：2025 年的对齐主线已经从"讨好人类"转向"可验证奖励"（RLVR）

**① GRPO 的工程本质：砍掉 critic，用组内相对分当基线。** DeepSeekMath（[arXiv:2402.03300](https://arxiv.org/abs/2402.03300)）提出的 GRPO 不再训练独立的价值网络（critic），而是**对同一个问题采样一组回答，用组内平均奖励当基线，每个回答的"优势"= 它比同组平均好多少**。工程收益是显存和通信成本大幅下降——PPO 的四件套（policy/critic/reward model/reference model）砍成三件套。这是 RL 阶段从"实验室技术"变成"团队可负担工程"的关键一步。

**② DeepSeek-R1：推理能力可以被纯 RL"逼"出来。** R1（[arXiv:2501.12948](https://arxiv.org/abs/2501.12948)）的路径分两步：**R1-Zero 不做 SFT 直接上 RL（GRPO + 可验证奖励：数学题对答案、代码跑测试），长思维链、自我反思（"aha moment"）等行为自然涌现**；但纯 RL 的输出可读性差、语言混杂，所以正式版 R1 补了少量冷启动 SFT 数据再做 RL。这个顺序之争有直接的工程含义：**"先有格式还是先有推理"——R1 的答案是可以先逼出推理、再修格式。**

**③ RLVR（可验证奖励的 RL）成为新范式，但它只覆盖"能判对错"的域。** 数学和代码有裁判（答案对不对、测试过不过），所以 RL 信号干净；而"写得好不好""回答得体不得体"没有裁判，只能靠 reward model——**而 reward model 会被 hack**。2025 年的研究（如 [arXiv:2502.18770](https://arxiv.org/abs/2502.18770)）系统性地指出：**RL 的 reward 不能无界，限制最大奖励或增强 KL 惩罚可缓解 reward hacking；工程上应把 reward scale 与 KL 系数当作同一个约束系统设计**，而不是分开调的两个旋钮。

**接回你的系统**：你的审查系统不在训练模型，但**思想同构**——第 19 讲的置信度校准本质就是给你的系统装一个"可验证奖励回路"：结论对不对要靠反馈数据闭环验证，而不是靠模型自己说"我很确定"。**"只信可验证的信号，对不可验证的信号设上限"——这条原则从 RLHF 训练房到你的生产系统，一字不改地成立。**

## 三、避坑清单

- [ ] **别把强化学习只当"玩游戏"**——它在 LLM 里最重要是 RLHF 对齐。
- [ ] **别把"对齐"当训练侧内部事**——你天天在用对齐成果（system prompt 好使），也天天承担其副作用。
- [ ] **别轻信对齐后的模型**——它可能为讨好而编造，你的系统要设结构化失败 + 评测（第 6/40 讲）。
- [ ] **读懂"为什么对齐难"**——奖励不可导 + 在线采样导致 PPO 又慢又不稳；DPO/GRPO 靠闭式解 + 组内基线把它化简。**能省就省，是这条线的第一原则。**
- [ ] **你的应用层也要有反馈闭环**，不能只靠模型"出厂就好"——记输出、回喂、持续校准。
- [ ] **把 RLHF 与你的反馈闭环当同一思想**——模型层和你的应用层对齐的是不同目标，但机制同源。

- [ ] **对齐后要做拒绝行为回归测试**——把历史上模型不该答应的请求过一遍，防止 DPO/RLHF 后模型变得"什么都顺着说"、丢掉了安全边界。

**步骤 3：把"反馈"翻译成"可计算指标"**

对照本讲"PPO 复杂 vs DPO 闭式"的启示，检查你的反馈闭环里**有没有哪一环节卡在"反馈太离散、没变成可计算的指标"**——把它量化成一条能进判断的分数，才算真正闭合。

**步骤 4：写一句"模型不可天生可靠"的判据进你的设计文档**

把本讲判据写成一句能在 review 里拦住"直接信任模型输出"的话，作为团队的共识。

## 本讲小结

1. **RLHF = 用人类偏好当奖励，靠强化学习让模型挑"人喜欢的"话说。**
2. **它解决"会说话但不知该怎么说话"**——让模型更听话、更少有害、更贴合人设。
3. **奖励建模用 Bradley-Terry**，强化目标 = max 奖励 − β·KL（防跑偏）。
4. **PPO 又贵又难（四件套+在线采样），DPO 靠闭式解砍掉奖励模型，GRPO 再砍掉价值模型**——同一目标的一路工程化简。
5. **副作用是"为讨好而编造"**——你的应用层要有自己的反馈闭环，持续校准。

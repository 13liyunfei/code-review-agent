## 一、痛点

你已经在 M1 讲过"模型只看得到三个字符串"，在 M2 讲"Agent 是带工具的循环"，在 M4 做了整套 RAG。但当你被问到"**它为什么这样输出？**"时，很多人会卡在两种回答上：

**第一种："因为它学习了全世界的数据。"** 听起来万能，但解释不了为什么它会上文不一致、会算错数、会一本正经胡说。**把"学习"当成黑箱，你就没法预测它的失败模式，也就没法设计兜底。**

**第二种："它是概率的，所以不可靠。"** 反过来说得对了一半，但接着往往滑向"既然是概率就没规律、碰运气、别想控制"——**这直接否定了你前 54 讲做的事，是一句自我否定的丧气话。**

本讲要破除的，是"黑箱崇拜"和"概率宿命论"两个极端。真相是：

> **模型的能力，可以用一句话精确描述：它不存储事实，不进行逻辑推理，它只做一件事——在给定上文后，按从海量文本中统计出的概率分布，预测下一个 token。** 你看到的所有"聪明",都是这一个动作被自回归地执行了几百上千次的结果。

**这一句精确描述，才是所有 Agent 设计的出发点**：因为模型"没有记忆"，所以你要给它记忆；因为"没有推理"，所以你要给它工具和循环；因为"没有事实库",所以你要给它 RAG。**模型的每一个短板，都对应你书里已经建过的一个机制。**

## 二、原理

### 2.1 模型到底存了什么

一个训练完成的大模型，存的东西本质上是**一组参数（数十亿到数万亿个浮点数）**，这些参数是训练时从海量文本里"压"出的统计规律。它**没有一张"北京=中国首都"的表**，它只有一个被压缩后的、用概率表达的"世界的样子"。

所以当你问"北京是哪个国家的首都"，模型不是"查表",而是**基于它学到的统计规律，估算出『首都』后面最可能是哪个词、『北京』相关的高概率下一个 token 是什么**。它给出正确的大概率，但**随时可能给出统计上"合理但事实上错"的答案**——这解释了第 6 讲为什么"空输出必须当失败"、第 35 讲为什么注入是真实威胁。

### 2.2 "预测下一个 token"= 自回归，而语言模型就是一条条件概率乘积

关键在"预测下一个"这四个字。用第 55 讲该有的严谨度重新表述：**一个自回归语言模型，把一段文本 x = (x₁, x₂, …, x_T) 的概率分解成一条条件概率的连乘**：

```
p(x) = p(x₁) · p(x₂|x₁) · p(x₃|x₁,x₂) · … · p(x_T|x₁,…,x_{T-1})
     = ∏ₜ p(x_t | x_<t)
```

每一步 `p(x_t | x_<t)` 就是"给定前面所有 token，预测下一个 token 的概率分布"。**你看到的大段回答、代码、对话，全是把这条链一个 token 一个 token 串出来的**——每推一步，就把刚预测的 token 放回上文，再做下一步：

```
输入："今天天气真"
 → 模型对词表里每个 token 给出概率（"好"0.7、"的"0.1、…）
 → 按策略选一个（不一定是最高）
 → 新输入变成"今天天气真好"
 → 再预测下一个……
```

这个"把自己的输出接回输入、再预测下一个"的循环叫**自回归（autoregressive）**。这条机制是理解很多工程现象的钥匙：

- **为什么上下文长度是硬上限？** 因为"上文"（x_<t）就是模型当前能看到的全部 token。超出就看不到，就"忘"了。→ 这是第 44 讲上下文压缩、第 12 讲上下文漏斗存在的根本原因。
- **为什么会产生重复、跑偏？** 因为每一步都只是"当前的条件概率最优",没有全局规划，串长了会累积偏误。→ 这是第 5、8 讲要让模型"用工具、走循环"来纠偏的原因。

### 2.3 那个"概率分布"长什么样：softmax + 温度 + 采样策略

"概率最高的词"这件事本身，值得再往下拆一层——因为它直接决定你要不要调 `temperature`，以及 `top_p` 是什么。有算法背景的你该知道这条链：

**第一层：模型输出一个「分数」z（logits）。** 模型最后一层对词表里每个候选 token（词表 V 通常几万到十几万）给出一个未归一化的分数 z = (z₁,…,z_|V|)，它不是概率。

**第二层：softmax 把分数压成概率分布。**

```
p_i = softmax(z)_i = e^{z_i} / Σⱼ e^{z_j}
```

Σᵢ p_i = 1，且每个 p_i ∈ [0,1]。这才是一个合法的"下一个 token 概率分布"。

**第三层：温度 T 控制分布的「尖锐 vs 平坦」。**

```
p_i = e^{z_i/T} / Σⱼ e^{z_j/T}
```

- **T→0**：分布收得极尖，几乎只选分数最高的那个 token（`贪婪解码 greedy`），输出**确定但容易重复、呆板**。
- **T=1**：原始分布。
- **T>1**：分布被抹平，低分 token 也能被选到，输出**更多样，但也更容易跑偏、胡说**。

**第四层：采样策略决定「从分布里怎么挑」。** 除了贪婪和解码温度，工程上高频的两个：

- **top-k**：只在分数最高的 k 个 token 里再采样（砍掉长尾）。
- **top-p（nucleus，核采样）**：按概率从高到低累加，取到累计概率 ≥ p 为止的这一小撮 token 里采样。它**自适应**——分布集中时只保留很少几个，分布平坦时保留更多，比固定 k 更稳。

**这对你 Agent 设计的直接意义**：**"模型输出的随机性"是一个可调旋钮，不是一个玄学**。你要稳定性（结构化输出、工具调用参数、代码生成）就把 T 调低、用 top-p 收紧；你要多样性（脑暴、文案、创意）就放宽。第 6 讲结构化输出里"凭什么还会偶尔出烂 JSON"，根就在这套 sampling 上——**只要 T>0 或用了采样，就没有 100% 确定这回事**。

**一张表把四种采样策略讲透**（你调 API 参数时的选型速查）：

| 策略 | 做了什么 | 适用场景 | 典型参数 | 坑 |
|---|---|---|---|---|
| **Greedy（贪婪）** | 永远选概率最高的 token | 结构化输出、工具调用参数、需要可复现 | T=0 / 无采样 | 输出呆板、容易重复、容易走进死循环 |
| **top-k** | 只在前 k 个最高分 token 里采样 | 创意写作、代码生成 | k=20~50 | k 固定，分布平坦时候选太少/太多（两头都不合适） |
| **top-p（nucleus）** | 按概率从高到低累加，取到累计 ≥ p 的最小集合 | 通用默认选项，大多数场景 | p=0.9~0.95 | 分布非常尖锐时仍可能只留 1 个 token（等价于 greedy）；分布平坦时候选集膨胀 |
| **min-p** | 候选 token 概率 ≥ p × max_prob（相对最高概率的比例阈值）| 高温度下的创意生成、2025 后新标配 | p=0.05~0.1 | 较新，部分推理栈还不支持（vLLM/SGLang 已支持） |

**工程判据**：**默认用 top-p=0.9 + T=0.7 是"稳而不僵"的工业基线**；需要确定性输出时降到 T=0.1 + top-p=0.3；需要放飞创意时 T=1.0 + min-p=0.05。**不要同时把 T 调很高又把 top-p 收很窄**——两者作用对冲，等于白花计算量。

### 2.4 推理时的计算账：生成一个 token 到底有多贵

对架构师和 harness 工程师，光知道"自回归"不够——你得能**估算生成 1000 个 token 要花多少算力、为什么长上下文更贵、为什么 batch 推理能摊薄成本**。直觉推导如下：

**① 自回归 = 生成 N 个 token 要跑 N 次前向。** 这是最基本的乘法：你要模型输出 100 个 token，它就得做 100 次完整的前向传播（从输入层到输出 softmax）。每次前向都要"过一遍所有层"。**这就是为什么 streaming 体验好——不是"算得更快"，而是"算一个吐一个"，你不用等 100 次全跑完再看**。

**② 每个 token 的计算量 ≈ O(L × d_model²)，与上下文长度 n 是加法关系（有 KV cache 时）。** L 是层数，d_model 是隐层维度。有 KV cache 时，新 token 只需要和缓存好的 K/V 做一次 attention，**新增计算量不随 n 二次增长**（但 KV 要读显存，所以 n 越大显存带宽压力越大）。没有 cache 的预填充阶段（prefill）是 O(n²) 的——这就是为什么"长上下文的第一个 token 出得慢，之后越来越流畅"。

**③ 把账换成你能懂的成本**：以 Llama 3 70B 为例，一个 A100 80G 卡每秒大约生成 15–30 个 token（长上下文更慢）。**1000 token ≈ 30–60 秒 ≈ 0.5–1 分钟的卡时**。云厂商按 token 收费时，你可以反推：他们的利润来自 batch（把多个请求拼一批算）和 MoE（稀疏激活）。**你的系统成本优化，本质上就是在和这件事较劲**——第 44 讲的上下文压缩省下的每一个 token，都是真金白银。

**④ 一个容易被忽略的事实：prefill 和解码是两种不同的计算。** Prefill（把整段提示词一次性塞进模型）是**计算密集型**（矩阵乘法多，并行度高）；decode（一个一个吐 token）是**显存带宽密集型**（每次算的量小，但要频繁读 KV cache）。**推理框架的优化（vLLM / SGLang）大半精力都花在"怎么把两种模式拼在一起省资源"上**——这也是为什么"同一模型，不同推理框架吞吐能差 2–5 倍"的结构性原因。

### 2.5 能力边界 → 机制需求：这本书的一张暗线

把这句话和你的书对一遍，你会发现**整本书的 Agent 机制，正是围着"预测下一个 token"的短板建的**：

| 模型短板（因为只会预测下一个）| 你书里对应机制 |
|---|---|
| 没有事实库 | M4 RAG（第 22–29 讲）给它实时知识 |
| 没有记忆 | 第 10、47 讲记忆状态机 |
| 没有确定逻辑 | 第 8 讲 Agent 循环 + 工具 |
| 记不住长上文 | 第 12、44 讲上下文工程 |
| 消耗按 token 计 | 第 32、33 讲成本计量 |
| 输出不可 100% 信赖 | 第 6 讲结构化失败、第 40 讲评测 |
| 输出有随机性（sampling）| temperature/top-p 调节 + 结构化兜底 |

**判据句（本模块的总纲）**：**一切 Agent 机制，都是对『模型只会预测下一个 token』这一短板的补偿。分析任何 Agent 产品，先问『它补了模型的哪个短板，用什么手段』。** 而"短板"的精确形状——软概率、自回归、sampling 随机性——就是本讲列出的这串公式。

### 2.5 前沿深挖：采样策略还在进化，"幻觉"已经有 token 级的可检测信号

top-k / top-p 是 2020 年前后的方案。2024–2025 年这条线又往前走了两步，对做 Agent 的人有直接用处：

**① min-p：比 top-p 更稳的长尾裁剪。** top-p 的问题是分布平坦时会放进一大堆低质候选。min-p（[arXiv:2407.01082](https://arxiv.org/abs/2407.01082)，ICLR 2025 接收）换了个裁法：**候选 token 的概率必须 ≥ p × max(概率)**——即以最高概率为基准的相对阈值，而不是累计概率的绝对阈值。分布尖锐时它自动只留头部，分布平坦时也不会把长尾全放进来。原文在多模型族上验证了"高温度下 min-p 比 top-p 更能同时保住创造性和连贯性"。**工程用法：做创意类生成（文案、脑暴）时，min-p=0.05~0.1 + T=0.8~1.0 是 2025 年开源推理栈（vLLM / SGLang 均已支持）的推荐组合。**

**② 幻觉不是玄学，是 token 级的统计信号。** 2025 年的几篇工作把"模型什么时候在胡说"从感觉变成了可计算量：

- **采样方差检测**（[arXiv:2507.04137](https://arxiv.org/abs/2507.04137)）：对同一个前缀采样多次，**低置信 token 在多次采样中的 log-prob 方差显著更大**——模型自己"拿不准"的地方，方差会替你报警。这是模型无关的黑盒方案，你的审查系统可以直接用：对关键结论性输出（如"这段代码有安全漏洞"）采样 3~5 次看方差，方差大就降级为"待人工确认"而不是直接回写 PR。
- **第一个幻觉 token 是不同的**（[arXiv:2507.20836](https://arxiv.org/abs/2507.20836)）：一段幻觉输出的**第一个出错 token** 的统计特征与其后跟着"将错就错"的 token 明显不同——这意味着幻觉检测应该盯住"起始 token"，一旦起始点被识别，可以 early-stop 重新生成，而不是等整段胡说八道完再兜底。

**把这两条接回你的系统**：第 40 讲的评测闭环管的是"事后算账"，这两个方向管的是 **"当场识别"**——在回写 PR 之前就给输出打一个可信度分。这正是"置信度校准"（第 19 讲）从离线校准走向在线推断的接口感。

## 三、避坑清单

- [ ] **别把模型当知识库或搜索引擎**——它是预测器，不是检索器；这个误会是 RAG 设计错位的第一来源。
- [ ] **别把模型的"输出"当成它有"记忆"**——上下文一换它就"忘",所以要给它记忆机制。
- [ ] **别把答案错归因于"它不够聪明"**——先问"它有没有被给足上文/工具/事实",大概率是你没给够。
- [ ] **用"只会预测下一个 token"这条来解释失败**——比"它是概率的"更能指向可修的工程手段。
- [ ] **面试答"模型怎么知道答案"要用本讲的精确句**，别停在"学习了全球数据"。

- [ ] **用温度做实验要固定变量**——同一个 prompt + 同一个模型，对比 T=0 / T=0.7 / T=1.5 三档输出，建立自己对"随机性"的直觉，而不是凭感觉调参数。

## 本讲小结

1. **大模型的聪明 = 给定上文，按概率预测下一个 token，再自回归串出来。**
2. **它没有记忆、没有推理、没有事实库**——这三个短板就是 Agent 机制存在的全部理由。
3. **上下文长度 = 它当前能看到的 token 上限**，超出即"忘"——这句解释所有上下文工程的必要性。
4. **一切 Agent 机制都是对模型短板的补偿**——分析任何 Agent 先问"补了哪个短板、用什么手段"。
5. **别停在"它是概率的"**，要用"只会预测下一个 token"去精确解释失败，并指向可修的手段。

> 📌 本讲代码锚点：本书不训练 LLM——**但你每天都在用它的三种能力形态**：预训练带来的"会语言"、涌现带来的"貌似推理"、对齐带来的"循规蹈矩"。读懂这三者，你就能解释很多奇怪现象：**为什么它啥都懂却又会一本正经胡说？为什么加了 system prompt 它就更"规矩"？**

## 一、痛点

你已经在 M1、M4、M7 大量使用 LLM，踩过各种奇怪现象：**它会一本正经胡说、同一句话换个说法它就听不懂、加了 system prompt 就"规矩"很多、换底座模型行为整体漂移。** 每个现象你都处理过（结构化失败、评测、降级），但可能没人把它们的**统一源头**给你讲清楚。

两个认知是错的：

**错误一："LLM 会这么多，说明它什么都会，直接让它干就行。"** → 你高估了模型的确定性逻辑，忘了它本质是"预测下一个 token"的统计产物——这解释它为何会胡说、为何同一个问题换个问法结果不同。

**错误二："想让模型听命令，就得重新训练它。"** → 你觉得只有"微调/训练"才能让模型听话，于是动不动想"训一个模型"，而忽略了你手里最便宜、最该先用的杠杆——**提示词与 Few-shot 已经在那了。**

本讲要破除的是"LLM 万能"和"只有训练才能控制"两个极端。真相是：

> **语言大模型是『预训练——学会会语言』+『涌现——貌似会推理』+『对齐——循规蹈矩』三件事叠出来的。** 预训练给了它"会说话",涌现让它在更大模型里"看着会推理",对齐让它在被要求时"好好回答"。**你的提示词不是重新训练，是在这套已有的能力上『调用 + 引导』——这决定了你能控制多少、该用什么手段控制。**

## 二、原理

### 2.1 预训练：在几十亿 token 上"学会会语言"

**预训练（pretraining）**：用一个巨大的语料库（网上几乎所有文本）训练模型，目标就是第 55 讲那句——预测下一个 token。用第 56 讲的交叉熵把它写成一条"训练目标"，就是**在整份语料上最小化下一个 token 的负对数似然**：

```
L_pretrain = − (1/T) Σₜ log p(x_t | x_<t)
```

模型在这里"学会"了**语言的统计规律**：词怎么搭配、句子怎么接、知识怎么表述。

关键不是"它背了多少知识"，而是 **"它学会了语言的分布"**。这区分了两件事：

> **"会背"（记住某些固定信息）≠ "会语言"（知道下一句怎么接）。** 模型是后者。所以它"全都懂"的不是一个知识库，而是一种**被压缩进参数的语言规律**。

### 2.2 一个预训练最该知道的公式：scaling law（缩放定律）

有算法/工程背景的你，看模型分"7B/13B/70B/405B"，一定会问：**参数翻倍，能力到底涨多少？有没有规律？** 有，就是 **scaling law**——它用一条幂律刻画"损失"随模型规模 N 与数据量 D 衰减：

```
L(N, D) ≈ E + A/N^α + B/D^β
```

- **E**：不可约误差（irreducible loss）——数据本身的混乱熵，是这条曲线的**下界**，再多参数也压不到它下面；
- **A/N^α**：随**参数数 N** 增大而减小的那部分误差；
- **B/D^β**：随**数据量 D** 增大而减小的那部分误差。

给这条式子的两个**工程结论**，影响你选型与预算：

1. **参数量和数据量要"配比"**——著名的 **Chinchilla 定律**说，在给定算力预算下，模型参数与训练 token 大致应该**同步放大**（约每 1 个参数配 20 个 token）。只堆参数不喂够数据 = 浪费；数据海量但模型太小 = 也吃不下。**这解释了为什么现在"小模型 + 海量数据"也能逼近大模型的单项能力。**

2. **收益是"边际递减"的幂律**：从 7B 到 70B 涨的是 α 次方级别的收益，但要烧 10 倍的算力。**所以"选多大的模型"是一个契合 scaling law 的算力-收益权衡，不是越大越好**——这也是你手里第 34 讲"多通道降级"、第 7 讲"用小模型兜底"背后的理论依据。

**scaling law 手算：给你一笔算力预算，最优模型和数据怎么配？** 用 Chinchilla 的结论（参数与数据应同步缩放，α≈β≈0.34，最优配比约 N:D ≈ 1:20，即 1 个参数配 20 个 token），你可以做非常实用的估算：

> **问题**：你有 1 万亿（1e12）FLOPs 的算力预算，最优 N 和 D 应该取多少？
>
> **Chinchilla 的经验关系**（算力约束下的近似最优）：
> - N ≈ C / 6（参数数 ≈ 总算力 ÷ 6）
> - D ≈ 20 × N（数据量 ≈ 20 倍参数）
>
> **手算**：
> - N ≈ 1e12 / 6 ≈ 1.7e11 → 约 170B 参数
> - D ≈ 20 × 170B = 3.4T tokens
>
> **换成现实中的模型对照**：
> - 7B 模型 → 约需 140B tokens → 总算力 ~ 42B FLOPs 量级
> - 70B 模型 → 约需 1.4T tokens → 总算力 ~ 420B FLOPs 量级
> - 400B 模型 → 约需 8T tokens → 总算力 ~ 2.4T FLOPs 量级
>
> **真实世界的验证**：DeepSeek-V3（671B 总参数 / 37B 激活）总训练成本 **2.788M H800 GPU 小时**（预训练 2664K + 上下文扩展 119K + 后训练 5K），和 scaling law 的估算在同一数量级——因为 MoE 的激活参数只有 37B，实际算力更接近一个 Dense 37B + 大量 token 的配比。

**这个手算给你三个工程直觉**：① **不要问"模型越大越好吗"，要问"我的预算对应的最优 N/D 是多少"**；② **数据比参数更稀缺**——凑参数容易（堆层加宽），凑高质量数据难，这也是 2024 年后"数据墙"成为瓶颈的原因；③ **MoE 本质上是用"总参数大、激活参数小"的方式在同样算力下吃进更多数据**——它绕开的不是 scaling law，而是把 N 换成了"激活 N"，用总参数的稀疏性换了更大的有效 D。

### 2.3 涌现：更大的模型，突然"貌似会推理"

当模型规模大到一定程度，一些**训练目标里没显式教的**能力会"冒"出来——少样本学习、切分任务、一定程度的多步推理。学术界叫**涌现（emergence）**。

**从 scaling 曲线看，涌现的形态很特殊**：损失 L 随规模是**平滑下降**的（第 2.2 节那条幂律），但某些**下游任务能力**却可能在某个体量处**突然从"随机水平"跳到"可用"**——像是"过了某个体量，这个任务突然就会了"。这正是"涌现"一词的由来，也是它**难预测**的原因：你无法只凭 loss 曲线的平滑下降，推断出哪个能力会在哪个规模点出现。

**注意这里的关键词是"貌似"**：第 55 讲已经确定它本质仍是"预测下一个 token"，只是随着规模和语料，这种"预测"展现出看起来像推理的连贯性。它**不是真正的逻辑推理**，所以会有第 5、8 讲里那个结论——**要给它工具、走循环来纠偏**，不能指望"想一想就行"。

### 2.4 对齐：SFT 先"学样"，RLHF/DPO 再"挑口味"

一个大模型直接训练完，可能会答出很多不被期望的输出。**对齐（alignment）** 让它学会"按人类期望的方式回答"。第 61 讲会展开 RL，这里先把**对齐的几个阶段**排清楚——因为这是你理解"模型为何听话"的关键：

1. **SFT（监督微调）**：先给一批"高质量（指令，理想回答）"对，用第 56 讲的监督训练让模型"照着学样"。**它解决"会语言但不会按指令办事"**——预训练只教"接话",SFT 教"听指令、产格式"。

2. **奖励建模（RM）**：收集人类对回答的**偏好排序**，训一个"打分器" r(x, y)，衡量"这个回答有多符合人类喜好"。

3. **强化学习微调（RLHF）**：用奖励 r 作为信号，通过 RL 让模型调整参数、**提高被奖励的回答的概率**。主流算法从 **PPO**（需要在线采样 + 价值模型，复杂、不稳定）演进到 **DPO（直接偏好优化）**——**DPO 把"强化学习"这一步的优化目标直接写成一条可计算的损失，不再需要单独的奖励模型与在线采样**，大幅降低了训练门槛与不稳定性：

```
L_DPO = −E[ log σ( β·[ log(π_θ(y_好|x)/π_ref(y_好|x)) − log(π_θ(y_坏|x)/π_ref(y_坏|x)) ] ) ]
```

（σ 是 sigmoid，β 控制"离参考模型多远",π_ref 是冻结的参考策略）。**一句话读这条式子：让"好的回答"相对于参考模型的概率上升、"坏的回答"下降，两者差距越大越好。**

**这对你的工程是一个巨大便利**：因为模型被对齐过，你才能用一个 **system prompt** 就"限定"它的角色和边界（第 11 讲）。它不是靠"训练成专家"来遵守你的规则，而是**靠对齐提供的『愿意配合』+ 你的 prompt 提供的『边界』**。

**判据句**：**分清『出厂能力』（预训练+涌现给的）与『你引导的』（prompt/Few-shot 给的）**。Few-shot 不是教它新东西，是**唤起**它已会的能力；如果唤起不起来（它真不会），你加再多 prompt 也白搭——这时候才轮到微调，而微调是你工程链上的昂贵选项，不是第一选项。

**训练三阶段管线：从"会说话"到"听话"到"说得好"。** 大模型的"出厂"不是一步到位的，是一条三阶段流水线。用一张图把三个阶段的关系说清：

> **图 59-1**　大模型训练三阶段管线。预训练（学会语言）→ SFT（学会听指令）→ RM + RLHF/DPO（学会按人类偏好说）。越靠前的数据量越大、成本越高；越靠后数据量越小，但对"对齐度"影响越大。

**三个阶段的成本-收益对比表**（看懂这张表，你就明白为什么"微调"不是你想做就做）：

| 阶段 | 数据量 | 算力占比 | 产出什么 | 你能做吗 |
|---|---|---|---|---|
| **预训练** | 万亿 tokens | **~90%** | 基础语言能力 + 涌现能力 | 几乎不能（太贵，除非大厂） |
| **SFT** | 十万~百万对 | ~5–8% | 指令遵循能力 + 格式输出 | 有数据+算力可以做（LoRA 更便宜） |
| **RM + RL** | 几万~几十万偏好对 | ~2–5% | 对齐度（有用、无害、诚实） | 小团队慎做（不稳定、难调参） |
| **后训练（DPO/GRPO）** | 几万~几十万偏好对 | ~2–5% | 对齐 + 推理能力 | 比 PPO 便宜，但仍需专业经验 |

**工程判据**：**90% 的能力在预训练，10% 在后训练决定"它听不听话、说不说人话"。** 你做 Agent 系统，绝大多数时候是在"用后训练的对齐红利 + prompt 引导"，而不是在改模型的基础能力。**当你觉得"模型不够好"时，先排查：是基础能力不够（得换底座），还是引导不对（改 prompt），还是对齐不好（考虑 SFT/DPO）？** 三个层次的成本差了两个数量级。

### 2.5 前沿深挖：scaling law 的下半场——数据墙、成本透明化与"涌现"的祛魅

**① Chinchilla 之后的真正变化：从"算力最优"到"数据墙"。** Chinchilla（[arXiv:2203.15556](https://arxiv.org/abs/2203.15556)）的遗产是 N 与 D 必须联合扩展；但 2024 年后约束从算力移到了**数据**——高质量公开文本基本被吃完，各家转向合成数据与数据课程。数据质量工程成为核心竞争力：HuggingFace 的 FineWeb、苹果/华盛顿大学的 DCLM 证明**同样 token 量下，数据清洗与配比能拉开可观差距**。"预训练"这三个字的技术含量，一半在数据管线。

**② 训练成本第一次变得可计算。** DeepSeek-V3 技术报告（[arXiv:2412.19437](https://arxiv.org/abs/2412.19437)）给出了行业罕见的完整账本：预训练 2664K GPU 时 + 上下文扩展 119K + 后训练 5K，**总计 2.788M H800 GPU 时**；关键降本手段是 **FP8 混合精度训练 + MLA + MoE + MTP（多 token 预测）** 的组合。这个透明化打破了"前沿模型必须上亿美元"的叙事，也给你一把标尺：**评估任何"我们训了个模型"的声明，先问 GPU 时账单和精度方案。**

**③ "涌现"正在被祛魅。** 第 2.3 节讲了涌现现象，但 2023 年的《Are Emergent Abilities of Large Language Models a Mirage?》（[arXiv:2304.15004](https://arxiv.org/abs/2304.15004)，NeurIPS 2023 最佳论文）提出了机制级质疑：**很多"突然涌现"是评估指标的阶梯化造成的假象**——用"全对才算对"的硬指标看，能力曲线是跳变的；换成连续的部分得分指标看，能力其实是平滑增长的。**这对你的评测设计有直接杀伤力：你在第 40 讲设计评测集时，指标的选择本身会决定你看到"平滑进步"还是"能力跃迁"——别把指标的伪影当成模型的神迹。**

**接回你的系统**：预训练的三件事——数据质量决定上限、成本可以被工程压缩、指标选择决定你看到什么——与第 40 讲评测闭环、第 20 讲内容准入是同构的：**质量与成本永远是一对，而测量工具本身会骗人。**

## 三、避坑清单

- [ ] **别把 LLM 当万能**——它是统计的，会胡说；要给它工具、走循环纠偏（第 8 讲）。
- [ ] **别想当然"训练一下就行"**——微调是昂贵选项，先确认 prompt/Few-shot 是否真的"唤起不动"。
- [ ] **Few-shot 是『唤起』不是『教新东西』**——它无关时加再多也没用。
- [ ] **system prompt 是引导不是门槛**——它建立在"模型被对齐愿意配合"之上，别指望它能教会模型做它没有的能力。
- [ ] **换底座模型整体漂移**——那是预训练数据的差异，你的系统要用熔断/评测应对（第 34/40 讲）。

- [ ] **换底座模型前先跑核心评测**——至少 20 条你场景里的典型用例，对比新旧模型的 pass rate，别光看参数表和 benchmark 就升级。
## 四、动手任务

> **目标**：用"出厂能力 vs 你引导的"框架，审视你对一个 LLM 的能力期待。

**步骤 1：把能力分两栏**

列一个你依赖 LLM 完成的任务，分两栏：**① 出厂能力（它本来会）② 你引导的（prompt/Few-shot 提供的）**。分不清的，就是你最容易失望/误判的地方。

**步骤 2：验证"是唤起还是硬教"**

对一件"你觉得它一开始不会、靠样例教会了"的事，问：**它到底是靠着 Few-shot 学会的（说明有基础），还是你其实解释了它原本做不到的？** 后者说明该换模型或简化任务，不是加样例。

**步骤 3：给"要不要微调"立判据**

梳理一条"先提示词 → 再 Few-shot → 还要微调"的判断路径，写清楚**什么信号出现才轮到微调**。别一上来就想训练。

## 本讲小结

1. **LLM = 预训练（会语言）+ 涌现（貌似推理）+ 对齐（循规蹈矩）。**
2. **"会背"≠"会语言"**——模型学的是语言分布，不是查知识库。
3. **涌现是"貌似推理"**——本质还是预测 token，要给它工具纠偏。
4. **你的提示词是『调用+引导』，不是重新训练**——分不清就会设计错。
5. **微调是昂贵选项**，先确认唤起不动，再考虑训练。

## 一、痛点

上一讲我们精确描述了模型**是什么**——一个预测下一个 token 的概率器。但有一个问题悬着：**它这些参数是谁写的？**

你几乎一定会脱口而出两种答案，而它们都不对：

**答案一："科学家设计出来的。"** 好像模型的行为是大神们逐行设计出来的，每个能力都精心安排。→ 这会让你高估模型的确定性，以为它"应该"每次都一样。

**答案二："它自己长出来的。"** 过度神秘化，当作不可解释的混沌。→ 这让你放弃理解，把一切归因于"玄学",也就放弃了用工程手段控制它。

**真相在两者之间，但要精确地说出来：**

> **模型的参数没有一行是"写"出来的，它们是训练时用亿万个『输入→期望输出』的例子，通过反复"看误差指出了哪个方向、就往哪微调"压出来的。** 你看到的"会说话、会写代码"，本质是这套"用数据压误差"过程跑了几百亿次参数的统计结果。

这一句让你获得两个实用的判断力：**① 为什么模型"不确定"（它是统计的，不是规则写的）；② 为什么"喂什么数据、怎么喂"决定能力边界（能力是压出来的，不是配出来的）**——第二条直接指导你怎么设计 Few-shot、怎么选样例（呼应第 11 讲提示词工程）。

## 二、原理

### 2.1 一个直觉：误差在哪，就往哪改

想象你要教会模型"1+1=2"。你给它输入 `1+1`,它胡乱预测了 `5`。误差显然在"输出不对"。你调权重，让它在看到 `1+1` 时更可能输出 `2`。再多看几百万个例子，它逐渐把加法这类规律"压"进参数里。

这就是监督学习的核心循环：

1. **前向（forward）**：输入进网络，得出一个预测。
2. **算损失（loss）**：预测和"正确标签"差多少，用一个数表示（越大越错）。
3. **反向传播求梯度（backward）**：误差"告诉"每个参数该往哪个方向调、调多少（梯度）。
4. **梯度下降微调（update）**：让参数沿着误差减小的方向动一小步。
5. **重复**：几百万次后，误差压到很小，网络"学会"了规律。

### 2.2 把这三步写成一个公式：损失 → 梯度 → 更新

对算法背景的读者，上面循环的数学形态是三条式子，背下来你就能看懂任何训练告警：

**① 损失函数（语言模型用交叉熵）。** 模型对下一个 token 给出概率分布 p（第 62 讲的 softmax 产物），真值 y 是"该出现哪个 token"。交叉熵衡量"预测分布离真值有多远"：

```
L = − Σ_c y_c · log p_c   （y_c 只在正确 token 处为 1，其余为 0）
  = − log p_(正确答案)
```

一句话：**损失 = 模型给正确答案的那个概率取负对数**。模型给正确答案 0.9 → L≈0.105；给 0.1 → L≈2.3。**概率越低，损失越大，而且是指数级惩罚——这就是为什么"很自信地错"比"有点犹豫地错"代价高得多。**

**② 梯度 = 该往哪调。** 损失是权重 θ 的函数，梯度就是它对每个权重的偏导：

```
∇_θ L = (∂L/∂θ₁, ∂L/∂θ₂, …, ∂L/∂θ_N)
```

**梯度向量指向"损失上升最快的方向"，所以往反方向走就是"下降最快"。** 反向传播（backprop）就是链式法则：从最后一层开始，把误差一层层往前乘回来，算出**每一个**参数的梯度——哪怕几十亿个参数，一次前向+一次反向就全算出来了。这是神经网络能"练"的核心原因之一。

**③ 更新 = 沿反方向走一小步。**

```
θ ← θ − η · ∇_θ L
```

η 是**学习率（learning rate）**。**η 太大**，一步跨过最低点、来回震荡甚至发散（loss 不降反升、变 NaN）；**η 太小**，收敛慢得像爬。实践中几乎没人用裸梯度下降，主流是 **Adam**——它给每个参数维护自适应的"步长",既看当前梯度、又看历史梯度的一阶/二阶矩，对稀疏梯度（词表里大部分 token 很少出现）尤其稳。**你在训练日志里看到 `lr`、`adam`、`grad_norm`、`loss=nan` 这些字段，现在知道它们在操作什么了。**

**反向传播的数值直觉：一个两层网络的手算例子。** 很多人听过"反向传播 = 链式法则"，但没真的推过一遍。用一个**极简的两层网络**走一遍，你就彻底懂了：

> 网络：输入 x → 第一层权重 w₁ → 隐层 h = w₁·x → 第二层权重 w₂ → 输出 ŷ = w₂·h → 损失 L = ½(ŷ − y)²（平方误差，比交叉熵算起来简单）。
>
> 已知：x=2, y=5（真值）, w₁=1, w₂=1。
>
> **前向**：h = 1×2 = 2，ŷ = 1×2 = 2，L = ½(2−5)² = 4.5。
>
> **反向（从后往前算梯度）**：
> - 输出层：∂L/∂ŷ = ŷ − y = 2 − 5 = −3（预测比真值小 3，损失随输出增大而减小）
> - 第二层权重：∂L/∂w₂ = ∂L/∂ŷ × ∂ŷ/∂w₂ = −3 × h = −3 × 2 = −6（w₂ 增大 1 单位，损失会减 6）
> - 隐层：∂L/∂h = ∂L/∂ŷ × ∂ŷ/∂h = −3 × w₂ = −3 × 1 = −3
> - 第一层权重：∂L/∂w₁ = ∂L/∂h × ∂h/∂w₁ = −3 × x = −3 × 2 = −6
>
> **梯度下降更新**（假设 η=0.1）：w₁ ← 1 − 0.1×(−6) = 1.6，w₂ ← 1 − 0.1×(−6) = 1.6。
>
> **再前向验证**：h = 1.6×2 = 3.2，ŷ = 1.6×3.2 = 5.12，L = ½(5.12−5)² ≈ 0.007。**一次迭代，损失从 4.5 降到 0.007。**

这个例子里你能看到三件事：**① 梯度是"从后往前"一层一层乘出来的（链式法则）**；**② 每层的梯度 = 后面传过来的误差 × 本层对输入的导数**；**③ 几十亿参数的大模型，无非就是这套东西乘上几万次矩阵乘法**。**理解了反向传播，你就理解了为什么"深层网络梯度消失"（误差乘了几十层小数字后趋近于 0）、为什么"残差连接能救梯度消失"（ResNet 的 skip connection 让误差有一条高速公路直接往前传）。**

### 2.3 优化器家族谱系：每一代解决了上一代的什么问题

梯度下降是 19 世纪就有的想法。但从 SGD 到今天的 Muon，中间每一代优化器都是在解决"上一代在深层网络上不够稳/不够快"的问题。一张谱系表看懂：

| 代 | 优化器 | 核心创新 | 解决了什么问题 | 新问题 |
|---|---|---|---|---|
| 0 | **SGD** | θ ← θ − η·g | — | 所有参数同一个学习率；对曲率不同的方向步长一样，收敛慢 |
| 1 | **Momentum（动量）** | 累积历史梯度的指数移动平均，沿惯性方向加速 | 梯度方向抖动的地方走得更稳；加速穿越鞍点 | 冲过最低点，来回震荡 |
| 2 | **RMSProp** | 每个参数自适应学习率（按历史梯度平方的 EMA 归一化） | 稀疏特征（词表）的参数梯度很小、更新慢，RMSProp 给它们更大的有效步长 | 分母可能趋近 0，步长爆炸 |
| 3 | **Adam** | Momentum（一阶矩 m）+ RMSProp（二阶矩 v）+ 偏差修正 | 集两者之大成；是 2015 年以来的默认标配 | 权重衰减和 L2 正则不等价（AdamW 修复）；二阶矩估计在大模型上有偏差 |
| 3.5 | **AdamW** | 把 weight decay 从梯度里拆出来，直接对权重做衰减 | 修复了 Adam 中 L2 正则与权重衰减不等价的问题 | 仍是逐元素自适应，对矩阵参数未必最优 |
| 4 | **Muon** | 对矩阵参数做 Newton-Schulz 正交化更新，不再逐元素 | 在大模型训练上比 AdamW 更快收敛，NanoGPT 基准连破纪录 | 只对矩阵形状参数有效，向量/偏置还用 AdamW；超参直觉不同 |

**工程判据**：**AdamW 是安全默认值**——99% 的微调场景（包括你的 LoRA）用它就对了。Muon 目前是前沿研究，只有从头预训练的团队才会折腾——**不要为了"用最新的"而把你可控的微调流程变得不可控**。

### 2.4 损失 / 梯度 / 批次：读懂训练的三个词

这三个词每天都在你的 LLM 工作里出现，读不懂会发懵：

| 词 | 是什么 | 你在哪见过 |
|---|---|---|
| **loss（损失）** | 预测对错的量化（交叉熵）| 评测里的"错误率"、"困惑度"；`exp(L)` 就是**困惑度 perplexity** |
| **gradient（梯度）** | 误差带来的"该往哪改"的方向 | 微调、LoRA 时的概念；`grad_norm` 是梯度的模，用于梯度裁剪 |
| **batch（批次）** | 一次喂多少个例子再更新 | 为什么"上一次和这一次"同一个 prompt 结果可能略不同 |

补充一个你一定会撞到的细节——**`perplexity = exp(L)`**：它把"平均每个 token 上模型有多不确定"换算成一个好读的数，直观含义是"模型预测时平均要从多少个等可能候选里挑"。perplexity 越低，模型越"笃定"。**你评估一个底座模型好坏、或看评测报告里的 PPL，就是这个东西。**

**它们共同造成一个你会反复撞见的现象**：**模型不是"稳定出厂"的，它是"训练出来的概率分布"**。所以同样输入，两次输出可能不同（采样随机性，第 62 讲）；换一个底座模型，行为可能整体漂移（预训练数据不同）。**你的系统必须在"模型会变、会漂、会不同"这个前提下才有韧性**——这正是第 34 讲熔断、第 06 讲结构化失败的原因。

### 2.5 过拟合：压"过头"的代价

训练最常见的坑是**过拟合（overfit）**：网络把"记住训练集里的特定答案"当成了"学会规律"。识别特征很清晰：

> **训练集上很准，但换一道没见过的题（测试集）就崩。**

更精确的判据是**看两条 loss 曲线的分叉**：训练 loss 持续下降，但验证集（validation）loss 在某个点后**掉头上升**——这一刻起，模型开始"背答案"而不是"学规律"，再训下去只会更差。**早期停止（early stopping）就是在这个分叉点收手。**

这个现象在你用 LLM 时有一个高度对应的形态——**提示词里的 Few-shot 样例**：

- 你给了几个"正确回答"的样例，若样例长得太像、把"规律"写成"背答案",模型遇到新场景就套错——这就是一种提示词层的"过拟合"。
- **对策与训练一致**：样例要**多样、覆盖变异**，而不是长得多像（呼应第 11 讲"A/B 分桶验证哪个更好"）。

**判据句**：**凡是"在见过的数据上很准，换新场景就崩"的现象，先怀疑过拟合——不管它是数千亿参数的网络，还是你 prompt 里的三个样例。** 而"过拟合"的精确形状，就是那两条 loss 曲线的分叉。

### 2.6 前沿深挖：优化器在换血，loss spike 有教科书级诊断法

**① Adam 的王者地位正在被动摇：Muon。** Adam 统治了十年，但 2024 年 Keller Jordan 提出的 **Muon**（[GitHub: KellerJordan/Muon](https://github.com/KellerJordan/Muon)）在 NanoGPT 速度赛上连续破纪录，思路完全不同：**对矩阵形状的参数（即占大头的隐藏层权重）不做逐元素自适应，而是对"更新矩阵"本身做 Newton-Schulz 正交化**——直觉是矩阵参数的更新也应该是一个"形态良好的矩阵"，而不是各坐标各走各的。月之暗面随后用 Moonlight 验证了 **Muon 可扩展到 LLM 规模训练**（《Muon is Scalable for LLM Training》，2025），Kimi K2 即用 Muon 变体训练。**工程含义：2025 年起看训练报告，先看 optimizer 一栏是 AdamW 还是 Muon——两者的超参直觉（lr 量级、weight decay 放哪）完全不同，不可混用经验。**

**② loss spike 不是玄学，有明确的前兆链。** GLM-130B 的技术报告（[arXiv:2210.02414](https://arxiv.org/abs/2210.02414)）留下了一个教科书级发现：**训练崩溃前，embedding 层的梯度会先于其他层出现数量级异常**——gradient norm spike 是崩溃的前兆信号，不是结果。所以你看到 `loss=NaN` 时才处理已经晚了，正确的监控对象是 **grad_norm 的时间序列**：突刺先于 loss 发散出现。2025 年的 AdaGC（[arXiv:2502.11034](https://arxiv.org/abs/2502.11034)）把这件事自动化：**按 tensor 粒度自适应裁剪**（用历史裁剪值的指数移动平均估计每个张量的正常尺度），核心收益是**防止一次异常梯度污染 Adam 的一阶/二阶矩状态**——Adam 的矩状态一旦被污染，后续几千步都在为那一步还债，这才是 spike 后"救不回来"的机制层原因。

**③ 学习率调度：cosine 之外有了 WSD。** 主流预训练从 cosine schedule 转向 **WSD（Warmup-Stable-Decay）**：预热后长期保持恒定 lr（stable 段），最后 10–20% 快速衰减。MiniCPM 与 DeepSeek 系的实践表明，WSD 的 stable 段随时可以"踩刹车"做 decay 得到一个不错的 checkpoint——**这把"训多长"从一个事前决策变成了事后决策**，对算力预算紧张的团队是决定性的工程自由度。

**接回你的系统**：你大概率永远不会预训练，但你会**微调**（LoRA/全参）。微调时的 loss spike、lr 选择、optimizer 默认值的坑与预训练同构——**看懂训练报告的这四个字段（optimizer / lr schedule / grad_norm / loss 曲线形状），你就有能力和算法团队平等对话。**

## 三、避坑清单

- [ ] **别把模型当"设计出来"的确定性机器——它是"压出来"的概率分布**，会变、会漂、会不同。
- [ ] **模型能力上限 = 训练数据的质量与覆盖**——所以 Few-shot 样例要多样、要覆盖，别当背答案。
- [ ] **"训练集准、测试集崩"= 先怀疑过拟合**，无论对象是模型还是你的 prompt 样例。
- [ ] **系统要在"模型会漂移"前提下有韧性**——熔断、结构化失败、评测闭环不是为了"模型不出错",而是因为"模型必然会变"。
- [ ] **读 loss/误差/评测数字时，先区分"在见过的数据上"还是"新场景"**——否则把过拟合当成了能力。

- [ ] **判断过拟合别只看 loss 曲线**——拿一组训练时没见过的样本做人工评测，loss 降了不代表泛化能力真的提了，很多时候只是"死记硬背"更熟了。
## 四、动手任务

> **目标**：用"训练/过拟合"的眼光，重新审视你的一个 LLM 交互设计。

**步骤 1：检查你的 Few-shot 是否"过拟合"**

打开你系统里带样例的 prompt（呼应第 11 讲），问：**样例是"覆盖了各种变异"还是"长得都像、在教背答案"？** 若是后者，加多样性。

**步骤 2：验证"换场景会不会崩"**

给你的一个 prompt 换一个你**没在样例里见过**的输入，看输出是否跑偏。跑偏，说明样例过拟合，改样例。

**步骤 3：把"模型必然漂移"写进设计**

选一个你依赖"模型这次会稳定输出"的地方，补上应对漂移的手段（熔断兜底、结构化失败、出厂后评测）。对照第 34 / 40 讲。

## 本讲小结

1. **模型的参数不是写出来的，是训练时用亿万个例子把误差"压"出来的。**
2. **训练循环四步**：前向预测 → 算 loss → 反传播求梯度 → 梯度下降微调 → 重复。
3. **能力上限 = 训练数据的质与量**——这对 Few-shot 设计有直接指导。
4. **模型是概率分布，会变会漂**——系统必须在"模型必然变"前提下有韧性。
5. **"见过的准、新的崩"先怀疑过拟合**——模型和 prompt 样例都适用。

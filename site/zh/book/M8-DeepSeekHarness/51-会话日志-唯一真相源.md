# 第 51 讲 · 会话日志：唯一真相源

> 🎯 导读问题：**"模型看到的历史，和系统记的那份日志，是同一份东西吗？"** ——能答出"必须是同一份，而且方向是**日志 → 历史**（历史是投影出来的，不是另存的一份）"——这一句就把你和"消息历史存一份、操作日志再存一份"的人分开了。**本讲要建立的判据是：「模型可见即已记录」（Model-visible means logged）——任何到达模型请求的内容，都必须能从日志重建。**

> **模块八 · 第三讲**：上一讲的三个动作里，有一个产出了 `dsh` 里最重的对象——`ctx.sessions` 上那本**仅追加的会话日志**。这一讲拆它。为什么它值得单独一讲？因为**fork、恢复、transcript（文本记录）、遥测、持久化五个消费者全都从它派生**——它是"一份真相，多个视图"这条原则在一个真实 harness 里的完整落地。
>
> **对研究员的落点**：你做实验最怕的是"这次跑的结果和上次对不上，但说不清差在哪"。**一份可重建的日志，就是把"说不清"变成"能重放"的那件工具。**

> **图 51-0**　本讲地图：会话日志是唯一真相源，**模型历史是从它投影出来的**（`deriveMessages()`），不是另存的一份。于是 fork / 恢复 / transcript / 遥测 / 持久化五个消费者共享同一份事实。而"推理"与"失败重试"在日志里被刻意分开成两类事件。

## 一、痛点

一个 Agent 系统跑起来之后，你会同时有这些需求：

- **要能中止再继续**（进程挂了，会话得能从断点接上）；
- **要能导出给人看**（"这次审查它到底做了什么"）；
- **要能算账**（token、耗时、成本）；
- **要能 fork**（"从第 3 步分岔，走另一条路试试"）；
- **要能落库**（换台机器接着跑）。

**绝大多数系统的做法是：每一项存一份。** 消息历史存一份给模型，操作日志存一份给人看，统计另开一张表，快照再存一个文件。

然后就是那件必然会发生的事——**它们开始互相漂移**。日志里显示"调用了一次工具"，但快照里没有那条结果；统计表记了 3 次重试，消息历史里只有 1 次。**而且没有任何一处会报错**，因为它们各自都是"自洽"的。

> **同一份事实存两遍，就一定会分出两种版本。** 差别只是你什么时候发现——以及发现时能不能对上。

`dsh` 对这个问题的答案是**极端**的：**只存一份**。会话日志是"agent 交互的、merge-extensible 的、仅追加的真相源；消息历史由该日志派生"（`docs/subsystems/session.zh.md:22-25` 原文：*"The merge-extensible, append-only source of truth for an agent interaction. Message history is derived from this log."*）。

**注意派生方向**：不是"日志从消息历史记下来"，而是**消息历史从日志投影出来**。方向反过来，一切都变了——**日志成了真的，历史成了视图。**

## 二、原理

### 2.1 `deriveMessages()`：从日志投影出模型历史

这是本讲的核心机制（`docs/subsystems/session.zh.md:670` 原文）：

> `Session.deriveMessages()` 将事件日志投影为模型看到的 `Message[]`。它是**缓存的**……且**冻结的**……`deriveEventMessage(event)` 是折叠所应用的**逐节点纯函数**，公开暴露以便外部重建器和开发不变式检查能以完全相同的规则投影日志前缀，不会与缓存产生分歧。

三个性质，每一个都有工程含义：

**① 缓存**：JSDoc 写着 *"CACHED: pure tail growth costs O(new nodes)"*（`:657`）——**尾部追加只花"新增节点"的代价**。这条很重要：它意味着"每跑一步就把整段历史重投影一次"这种 O(n²) 的做法是不必要的。

**② 冻结**：JSDoc 写着 *"Consumers cannot mutate the log through either form."*（`:657`）。**投影结果不可改**——因为一旦有人就地改了它，"日志是真、历史是视图"这条就断了。冻结是把这条纪律**做成运行时约束**，而不是靠约定。

**③ 逐节点纯函数**：`deriveEventMessage(event)` 被单独**公开导出**，让"外部重建器"和"开发不变式"用**完全相同的规则**投影——**不能有两份投影实现**。

**★ 判据句（本讲第一个架构判据）**：

> **"投影函数必须被复用，而不是被重写。"** 只要有第二个地方需要"从日志算出模型历史"（调试器、回放器、不变式检查），就必须调用同一个函数。**两份投影实现 = 两份历史**——这正是第 43–48 讲讲过的"同一功能两套实现必然漂移"，只不过这次漂移发生在**日志与历史之间**。

**投影规则是白名单式的**（`:672-677`）：

| 日志事件 | 投影为 |
|---|---|
| `user/message` | 携带确切 content 的 user 消息 |
| `assistant/message` | 含"生成它的提供方与模型"的 assistant 消息（嵌入的紧凑 stream 是**回放/usage/UI 的证据**，**不是**第二条 message） |
| `tool/result` | 一等 tool-role 消息 |
| 注入上下文的 `user/message` | 按时间顺序生成 user-role 消息 |
| `turn/*`、`step/*`、`assistant/attempt`、插件所属 `llm/retry` | **结构信息，不投影为消息** |

注意两点克制：**内容为空的 `assistant/message` 会被跳过**；**失败的重试不进历史**。

### 2.2 `assistant/message` vs `assistant/attempt`：把"推理"与"失败"分开

这是本讲**最容易讲错、也最值得学**的一处设计。原文（`docs/subsystems/session.zh.md:87-101`）：

- `assistant/message`：某一步组装后的 assistant message（**派生历史用它**），携带可选的 `usage`、`interrupted?: true` 与嵌入 stream。
- `assistant/attempt`：*"One model attempt that committed no surface message. The embedded stream preserves a failed, retried, cancelled, or stream-error attempt that reached settlement **without fabricating model-visible history**."* —— 一次**没有提交任何 surface message** 的模型尝试；嵌入 stream 保留"到达结算（settlement）的失败 / 重试 / 取消 / stream-error"，**且不虚构模型可见历史**。

**这两个事件的分工，是一条可以直接搬走的判据**：

> **"发生过的事"与"模型看见的事"是两种事实，必须分表存放。** 一次失败的重试**发生过**（你要排查、要计费、要算重试次数），但它**不该让模型相信"我说过那句话"**。如果你把失败尝试也写进历史，模型下一轮就会看到"自己说过一段没说过的话"——**这就是幻觉的一个工程来源，而且是可避免的那种**。
>
> **实操落点**：日志需要**两类事件**——一类"进历史"，一类"只记账"。混成一种，你会在"要完整"和"要干净"之间反复妥协。

还有一条精确的约束：`assistant/message` **不能携带** `sourceEventSeqs`——因为它自带的 `stream` 就是精确的提供方证据（`:362`）。

### 2.3 核心不变式：「模型可见即已记录」

现在可以给出这整套设计的那条不变式了（`docs/architecture.zh.md:129` 原文）：

> **模型可见即已记录。** 运行时不变量检查**模型请求是否可从日志重建**。新增模型可见输入需要会话事件。

英文版同义（`docs/architecture.md:125`）：*"**Model-visible means logged.** A runtime invariant checks model requests are reconstructable from the log."*

约定级出处是把这条写成了硬规则的地方（根 `AGENTS.md:136`）：

> **Model-visible ⟺ logged**: anything that reaches a model request must be reconstructable from the session log; a new model-visible input requires a session event.

**"运行时检查"具体检查什么？** 这里有一段很值得看的实现描述（`docs/subsystems/llm-streaming.zh.md:749`）：

> 开发不变式针对**每个循环构建的请求**精确重算此等式，并拒绝携带 `system` 字段的循环请求。

以及请求为何**能**被重建（`:745`）：

> `request/header` 记录权威返回工具顺序（`toolOrder`，未配置按字典序），渲染后的提示词是派生历史（surface 第 0 号节点上的 `system/message`），二者共同使请求可由日志重建。

**★ 判据句（本讲第二个架构判据，也是这一模块最"能搬走"的一条）**：

> **"能重建"是一个可测试的等式，不是一个形容词。** `dsh` 的做法是：**针对每一个真实构建的请求，重算一遍"从日志投影出的历史"，然后比对是否相等。** 不等就报错。
>
> 这条为什么值钱？因为它把"我们的日志很全"这种自我评价，变成了一条**每次运行都在跑的断言**。对照你自己的系统："我记了日志"和"我能从日志重建出模型看到的一切"**是两件事**——后者需要有人**真的去比对过**。而这条比对的成本极低、抓的 bug 极贵（幻觉、错乱、不可复现的评测差异）。

### 2.4 投影 seam：增量折叠 + `stateOf()` / `snapshot()`

日志有了，还需要给 UI、给外部工具**读**它的能力。这一层是 `dsh-session-projection`（`docs/architecture.zh.md:131` 原文）：

> `dsh-session-projection` 提供 `ctx.sessionProjections`：已注册单元**增量折叠**已提交事件，host 消费方通过 `stateOf()` 读取单个类型化状态，载体通过 `snapshot()` 批量取得**裁剪后的客户端视图**。

两个 API 的语义差别值得记（`docs/subsystems/session-projection.zh.md:102` 原文）：

> `snapshot(session)` **完全同步**：载体在切出页面切片的同一 tick 内读取它，因此 `asOfSeq` 使两次读取使用**同一个序号**。它只返回客户端视图，并在返回前通过各单元的 `viewSchema` 校验。`stateOf(session, key)` 可在**不计算无关视图**的情况下读取一份实时 host 状态；调用方不得修改这一借用引用。

**"同一 tick、同一序号"** 解决的是分布式 UI 的经典问题：两次读取之间数据变了，页面就自相矛盾。**把"一致性读"做成 API 的语义，而不是调用方的纪律**——这是很干净的做法。

驱动方式（`:106`、`:207`）：注册表**只订阅一次** `session/event`，把每个已提交事件**即时**传给每个注册单元的 `apply`；state 引用变化才计算并缓存 view；只有原始 view 结果按 `Object.is` 变化才触发变更流。

**而"注册是 effect"这条纪律在这里一样生效**（`:106`）：

> cell 惰性构建……**注册是一个 effect，其 disposer 随调用方 fiber 走**

⇒ **领域插件卸载后，key 连同缓存 cell 从后续驱动与快照中消失**，客户端把它读作"能力缺失"。同 key 不同 `stateVersion` 直接 throw；同版本注册方共享一个 cell 并被计数。

### 2.5 前沿深挖一：版本演进——为什么"每包只走一步"

日志要长期活着，就必须能改格式。`dsh` 的迁移纪律有两条硬线。

**第一条：命名与分代**（`docs/architecture.zh.md:127` 原文）：

> JSONL v0 使用 `session.jsonl[.zstd]`，v1 及后续版本使用小写 `session.vN.jsonl[.zstd]`；**已提交 generation 路径绝不重命名、替换或删除。**

**第二条：迁移链是相邻的**（同段原文）：

> 每个相邻迁移包只负责一个 `vN -> vN+1` 步骤。

生成器把这条约束做成了**机械检查**（`docs/cookbook/adding-a-session-format-version.zh.md:48`）：从零到当前写入器版本，**每一步恰好有一个相邻迁移包**，目录与包名匹配、相邻 codec 导出匹配；**拒绝缺口、重复或多余迁移边**。而"当前写入器版本"只有一个手工维护的地方——`SESSION_FORMAT_VERSION`（`docs/session-format-status.zh.md:20`）。

**★ 判据句（本讲第三个架构判据）**：

> **"每包一步"把 N 个版本的迁移成本从 O(N²) 组合降到 O(N) 线性。** 如果允许"v1 → v4 的直达迁移"，那么每次加新版本，你要维护的组合数是版本数的**平方**；而相邻链只要求**每一步**存在且被测试过。
>
> **"绝不重命名 / 替换 / 删除已提交路径"** 是同一件事的另一半：**已经写出去的格式是契约，不是草稿。** 你不能"把 v1 文件改名为 v2 并改 header"——那不是迁移，那是伪造历史。（同页还有两条同族禁令：绝不以零替代未知截点、绝不通过改写已提交代际来修集成问题，`:31`、`:57`、`:83`。）

顺带一个**方向性**的细节值得注意（`docs/subsystems/persistence.zh.md:189`）：

> 当前格式恢复会保留已安装扩展和带 `ignorable: true` 的未知事件；**历史 v0/v1/v2 迁移则会拒绝未知类型，即使它带有 ignorable 标记。**

⇒ **同一份日志，从"当前格式"读和从"历史格式"读，对未知事件的宽容度是相反的。** 原因很实在：**新格式"多出来的东西"可能是别人装的扩展，宽容是对的；老格式"多出来的东西"更可能是版本不匹配，拒绝才安全。**

另外，持久化这一层本身是**纯 seam**（`docs/subsystems/persistence.zh.md:7`）：`ctx.sessionPersistence` 在**现有的 `SessionEvent` 之上**暴露 `create`/`open`/`stat`/`list`，**没有平行的"持久化事件类型"**。**换一个后端（本地文件 / 数据库 / 云）不改事件词汇**——这就是上一讲"通过 key 查找而非导入实现"在存储层的体现。

### 2.6 前沿深挖二：一次真实事故——当快照把 bug 接受成了"预期"

再讲一个事故（`docs/postmortem/0002-js-expression-disabled-filesystem-tools.zh.md`）。它和第 50 讲的 0001 是同一族失效，但这次**坏的是"验证方式"本身**。

**执行摘要**（`:9` 原文）：

> ACP 示例试图通过 `disabled: !!js ...` 有条件地启用文件系统插件，但 Cordis **仅在插件 `config` 内部**对 JavaScript 表达式求值。原始的表达式对象为 truthy，因此文件系统栈**始终处于禁用状态**。快照刷新随后将 `UNKNOWN_TOOL` 结果**接受为新的预期输出**。

**根因很具体**（`:32` 原文）：

> 实际只有 `entry.options.config` 使用它：`Entry._resolveConfig()` 对该字段插值，而 `Entry.disabled` 直接测试 `entry.options.disabled`，不经过插值。**YAML 标签在语法上合法，因此加载过程不产生任何诊断信息。**

⇒ **"语法上被接受"不等于"在这个位置被求值"。** 一个完全合法的 YAML 标签，写在了不被求值的位置，就变成了一个**永远为真的字面量对象**。

**但最值钱的是第二步事故**（`:19` 原文）：

> 快照套件通过了，因为结构化会话日志和 stdout 渲染出的通用失败工具卡片均与刷新后的 fixture（测试前置数据）匹配；**它证明的是回归的确定性回放，而非文件系统行为的正确性。**

以及教训里那句（`:46`）：

> **快照刷新是 fixture 的生产过程，不是正确性审查。** 诸如已注册工具缺失这类语义上不可能的结果，需要独立于预期输出的断言。

**★ 判据句（本讲第四个架构判据，也是"日志即真相源"的阴暗面）**：

> **日志是真相源，但"日志里有这一条"不等于"这一条是对的"。** 快照测试比的是"这次输出和上次一样吗"——**当 bug 是稳定的，快照会把它稳定下来，并称之为正确。**
>
> 所以"唯相源"必须配一条**独立于预期输出的断言**。`dsh` 的防护正是这个形状（`:38-41`）：① 文件系统场景启动**显式**固定全权限 overlay；② 把 `!!js` 的生效范围写进 `AGENTS.md` 与 Cordis 入门；③ `verify-cordis-config` **解析**仓库 Cordis YAML 并**拒绝** loader 配置项元数据中的表达式节点；④ `dsh-session-snapshot` **在全新运行和已提交会话 fixture 中拒绝结构化 `UNKNOWN_TOOL` 结果**。
>
> 第 ④ 条尤其值得抄：**它没有去比"输出对不对"，它直接禁止了一类"语义上不可能出现的结果"**。**这是"独立断言"该有的样子。**

## 三、避坑清单

- [ ] **别把消息历史和操作日志存两份。** 只存日志，历史一律投影出来；否则漂移必然发生且不报错。
- [ ] **投影函数只能有一份实现。** 调试器、回放器、不变式检查都要**调用同一个**函数，不许各写一遍。
- [ ] **投影结果要冻结。** 一旦有人就地改视图，"日志是真、视图是派生"这条纪律就断了。
- [ ] **"发生过"与"模型看见过"分表。** 失败 / 重试 / 取消进"只记账"那类事件，**绝不进模型历史**——否则你在给幻觉供料。
- [ ] **把"能重建"写成每次运行都跑的断言**，而不是写在文档里。方向是：用日志投影一遍请求，与真实请求比对。
- [ ] **迁移要相邻，每包一步。** 允许跨版本直达迁移，维护成本是版本数的平方。
- [ ] **已提交的格式路径不改名、不替换、不删除。** 那是契约，不是草稿。
- [ ] **"当前格式"和"历史格式"的容错方向是相反的**：新格式保留未知事件，老格式拒绝未知事件。
- [ ] **快照测试会把稳定的 bug 稳定下来。** 必须补独立于预期输出的断言，尤其是"语义上不可能的结果"这类。
- [ ] **日志是真相源，不是正确性证明。** "记录得全"与"内容是对的"是两个命题。

## 四、动手任务

> **目标**：亲手证明"一份日志能重建出模型看到的一切"，并给自己的系统补一条独立断言。

**步骤 1：打开一份真实日志**

跑一次 `dsh`，找到它的会话文件（v0 是 `session.jsonl`，v1+ 是 `session.vN.jsonl`）。**任务**：逐行读，把事件按 2.1 节那张表**分成两栏**——"会进历史的"和"只记账的"。**验收标准**：你要能指着某一行的 `assistant/attempt` 说"这条模型看不见"。

**步骤 2：手工重建一次请求**

从日志里挑一个 `assistant/message`，按投影规则**手工**重建出它当时的输入侧（system + 历史消息 + 工具列表）。**任务**：找到 `request/header`，确认它记的 `toolOrder` 与你重建出的工具顺序一致。**这一步做通了，2.3 节那条不变式对你就从"文档说法"变成了"我验过"。**

**步骤 3：写一条"独立于预期输出"的断言**

针对你自己的系统，写出**一条**这样的断言：它不比对"输出是否和上次一样"，而是直接**禁止一类不可能的结果**（例：`UNKNOWN_TOOL` 不得出现在任何会话日志里；某工具调用不得出现在它未被注册的轮次里）。**任务**：说明它为什么**不依赖**预期输出的正确性。

**步骤 4：检查你的"重试"进了哪里**

回答：**你系统里失败重试的记录，会不会进模型下一轮的输入？** 如果会，这就是一个正在供料的幻觉来源。给出修法（拆成两类事件）。

## 本讲小结

1. **只存一份，方向是"日志 → 历史"。** 会话日志是唯一真相源，模型历史由 `deriveMessages()` **投影**出来；投影结果**缓存 + 冻结**，投影函数**逐节点纯函数且公开复用**。
2. **白名单投影 + 两类事实分开。** `user/message` / `assistant/message` / `tool/result` 进历史；`turn/*`、`step/*`、`assistant/attempt`、`llm/retry` 只作结构信息。
3. **`assistant/message` 与 `assistant/attempt` 的分工是一条可搬走的判据**："发生过"与"模型看见过"分表存放——失败重试要记账，但**不能虚构模型可见历史**。
4. **核心不变式是「模型可见即已记录」**，而且它是**可测试的等式**：针对每个真实构建的请求，用日志重算一遍历史并比对。不用比对的日志，"全"只是一种自我评价。
5. **投影 seam 提供增量折叠 + `stateOf()` / `snapshot()`**，其中 `snapshot` 的"同一 tick、同一序号"把一致性读做成了 API 语义；注册是 effect，插件卸载 ⇒ 视图与缓存一起消失。
6. **版本演进两条硬线**：每包只走一步（O(N) 而非 O(N²)）、已提交路径绝不改名替换删除。且**"当前格式"与"历史格式"对未知事件的容错方向相反**。
7. **日志是真相源，但"记下了"不等于"是对的"。** 快照会把稳定的 bug 稳定成"预期"——所以必须补**独立于预期输出**的断言（`dsh` 的做法是直接拒绝"语义上不可能的结果"）。

下一讲我们走到那个"连它自己都能被替换"的位置：**Agent Loop**。一个**步骤**是一次模型请求加它调起的工具，一个**轮次**包含零个或多个步骤——而这套循环把"拦截点"全部做成了**瀑布事件**。我们要回答：**为什么"轮次收尾"这件事偏偏不用瀑布、也不用 `next()`。**

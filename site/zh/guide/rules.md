# 规则引擎

规则是系统的检测知识，写在 **YAML 而不是 Java** 里。加一条规则是配置变更，不是代码变更。

## 规则长什么样

```yaml
rules:
  - id: SEC-001
    title: "字符串拼接导致的 SQL 注入"
    severity: BLOCKER
    patterns:
      - "executeQuery\\(\\s*\".*\\\"\\s*\\+"
      - "createStatement\\(\\)"
    suggestion: "改用参数化查询（PreparedStatement），不要字符串拼接。"
```

## 规则构成

| 字段 | 含义 |
|------|------|
| `id` | 稳定标识，报告与反馈都引用它 |
| `title` / `severity` | 展示与分级（INFO / MAJOR / BLOCKER） |
| `patterns` | 分析器检查的正则或 AST 模式 |
| `suggestion` | 附加到行级评论的修复文案 |

## 规则存放位置

规则按团队解析：

- 引擎自带**全局基线**
- 每个团队在基线上叠加自己的规则
- 团队配置缺失时回退基线

这与自定义 Agent、知识库用的是同一套多租户模式。

## 两条分析路径

1. **AST 分析** —— 结构性检查（资源泄漏、分层违例），走 `AstAnalyzer`
2. **模式扫描** —— 正则类检查（硬编码密钥、危险 API），走模式技能

两者产出相同的 `Finding` 结构，下游聚合一视同仁。

## 反馈闭环

被驳回的发现（误报）流经工作流引擎——同一规则反复被驳回会被降级，规则集从团队判断中学习。

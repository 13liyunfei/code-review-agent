# 自动修复

携带明确修复方案的发现会附带**行级建议**，SCM 以行内提案形式呈现。

## 工作原理

引擎为每个可修复的发现附加 `suggestion`，回写时定位到精确行发布为审查评论，开发者在同一位置看到问题与修复。

```
if (rs.getInt("stock") < qty) { ... }
^^^
SEC-001: 字符串拼接导致的 SQL 注入
修复：改用参数化 PreparedStatement 查询
```

## 什么可修复

不是所有发现都能修——只有规则定义了**确定性 `suggestion`** 的才作为可修复发布。含糊的、依赖模型发挥的建议留在概览报告里，不假装成机械修复。

## 护栏

- 修复是**建议不是改动**——不会自动提交任何东西
- 审查者在编辑器 / SCM 里一键采纳
- 修复后可走复检流程验证变更并清除该发现

## 修复后复检

开发者采纳修复后，增量验证路径会重跑相关检查，确认发现是否已解决——闭合"已建议"到"已完成"的环。

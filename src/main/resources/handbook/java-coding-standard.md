# 团队 Java 编码规范（示例）

## 数据库访问
- 所有数据库查询必须显式列出所需字段，禁止 SELECT *，避免无效 IO 与索引失效。
- 禁止将外部输入直接拼接进 SQL 语句，必须使用参数化查询（PreparedStatement）或预编译语句。
- 高频查询字段应建立合适索引；避免在循环中执行数据库查询（N+1 问题）。

## 安全
- 禁止在代码中硬编码密码、Token、API Key 等敏感凭证，应统一由配置中心或 KMS 托管。
- 所有外部输入在落入 SQL、命令、LDAP 等上下文前必须做校验与转义。

## 异常处理
- 禁止空 catch 块吞掉异常；至少记录日志，必要时向上抛出。
- 禁止使用 e.printStackTrace()，统一使用日志框架（SLF4J）记录异常堆栈。
- 生产代码禁止使用 System.out 输出，交由统一日志组件管理。

## 并发与性能
- 禁止在业务代码中随意 new Thread()，应使用统一线程池（如 Spring TaskExecutor）。
- 方法级 synchronized 需谨慎，高并发场景应缩小锁粒度或使用并发容器。

## 代码风格
- 单行长度建议不超过 120 字符，过长应拆分或抽取方法。
- 禁止在提交中遗留 TODO / FIXME 等未跟踪标记。
- 保持代码整洁，去除行尾多余空白。
